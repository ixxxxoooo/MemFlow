# 跨平台适配说明

MemFlow 最初只面向 macOS。本文记录 0.2.0 起对 Windows / Linux 的适配方式、取舍与已知差异,供贡献者在改动平台相关代码时参考。

## 1. 平台支持矩阵

| 项目 | macOS | Windows | Linux |
| --- | --- | --- | --- |
| 官方安装包 | `.dmg`(aarch64 / x64) | `-setup.exe`(NSIS,x64) | 暂无,从源码构建 |
| CI(clippy + 测试) | ✅ | ✅ | ✅ |
| 本机 OCR | ✅ PDFKit + Vision | ❌ | ❌ |
| 窗口效果 | 毛玻璃 + 红绿灯叠加标题栏 | 实色窗口 + 系统标题栏 | 同 Windows |
| 凭据存储 | 钥匙串 | 凭据管理器 | Secret Service |

## 2. 适配点与实现

### 2.1 配置拆分

- `src-tauri/tauri.conf.json`:跨平台基础配置(普通带标题栏的不透明窗口、`bundle.targets = "all"`、NSIS 设置)。
- `src-tauri/tauri.macos.conf.json`:macOS 覆盖配置(透明窗口、`titleBarStyle: Overlay`、红绿灯位置、`dmg`、`signingIdentity: "-"`)。Tauri 以 JSON Merge Patch 合并,**数组整体替换**,所以 macOS 文件重复了完整的 `app.windows`。
- `macOSPrivateApi` 与 Cargo 的 `macos-private-api` feature 必须同时开启,故保留在基础配置中(其它平台无副作用)。

### 2.2 凭据存储(`secrets.rs`)

- `keyring` v3 按目标平台启用对应后端(`apple-native` / `windows-native` / `sync-secret-service`)。
- 服务名 `com.ixxxxoooo.memflow`;仅 macOS 保留旧服务名 `com.memflow.app` 的读取与迁移。
- macOS 判断「是否已有密钥」用 `/usr/bin/security` 查询(不读取密文,避免钥匙串授权弹窗);其它平台直接读凭据库。
- 凭据库不可用(如无桌面会话的 Linux)时,`set_key_for` 把密钥保存在内存并提示「仅本次运行有效」,功能不中断。

### 2.3 Ollama 发现与启动(`ollama.rs`)

- 候选路径 = `PATH` + 各平台常见位置(macOS:`/Applications/Ollama.app`、Homebrew;Windows:`%LOCALAPPDATA%\Programs\Ollama`、`Program Files`;Linux:`/usr/local/bin`、`/usr/bin`)。
- macOS 优先打开 Ollama.app;其它平台以 `ollama serve` 子进程启动,Windows 使用 `CREATE_NO_WINDOW` 避免弹出控制台。

### 2.4 目录

- 数据:`local_data_dir()/MemFlow`(Windows 为 `%LOCALAPPDATA%`,避免大体积数据库被漫游同步)。
- 日志:macOS `~/Library/Logs/MemFlow`;Windows `%LOCALAPPDATA%\MemFlow\logs`;其它 `~/.memflow/logs`。
- 用户主目录统一经 `model_fetch::home_dir()`(`HOME`,回退 `USERPROFILE`)。

### 2.5 窗口与托盘

- `window-vibrancy` 仅在 macOS 目标下依赖与调用。
- 托盘:macOS 使用单色 template 图标;其它平台使用应用默认图标。
- 前端 `src/lib/platform.ts` 从 User-Agent 识别平台,启动时写入 `<html data-platform>`;CSS 对非 macOS 使用实色背景与 `--glass` 兜底,字体栈补充 Segoe UI / 微软雅黑 / Noto Sans CJK。
- 侧栏顶部为红绿灯预留的 52px 间距只在 macOS 生效。

### 2.6 快捷键

- 全局胶囊快捷键默认:macOS `Cmd+Shift+K`;其它平台 `Ctrl+Shift+K`。
- 应用内快捷键用 `metaKey || ctrlKey` 判定;界面文案通过 `shortcutLabel()` / `prettyAccelerator()` 按平台显示 `⌘` 或 `Ctrl+`。

### 2.7 本地重排序与 Intel Mac

`fastembed` 依赖的 `ort-sys`(ONNX Runtime)没有 `x86_64-apple-darwin` 预编译库。Intel Mac 安装包以 `--no-default-features` 构建(关闭 `rerank` feature):后端 `rerank_models` 返回 `engine: false`,设置页禁用该开关并说明原因,检索自动使用 RRF 融合排序。Apple Silicon、Windows、Linux 均启用。

### 2.8 原生 OCR 的取舍

OCR 依赖 macOS 的 PDFKit 与 Vision(`native/pdf_ocr.m`)。Windows(Windows.Media.Ocr)与 Linux(Tesseract)都需要额外的原生依赖或较大的运行时,本次未引入。非 macOS 的降级方式:

- PDF:只读文本层;扫描版 PDF 在设置里启用「视觉模型」逐页解析(本地 `minicpm-v` 或云端视觉模型)。
- 图片:保留图片与文档的关联,不识别图中文字;可用视觉模型生成描述。

后续如需补齐,可在 `ocr_worker.rs` 的非 macOS 分支接入对应实现,接口已按平台隔离。

## 3. CI / 发布

- `ci.yml`:前端检查(类型检查、构建、vitest)+ Rust 三平台矩阵(Linux 额外跑 `cargo fmt --check` 并安装 WebKitGTK 等依赖)。
- `release.yml`:推送 `v*` tag 触发。`prepare` 校验版本一致并用 CHANGELOG 生成发布说明、创建草稿 Release → `build` 矩阵(aarch64 dmg、x64 dmg、Windows NSIS)上传到草稿 → `publish` 校验资产数量(2 dmg + 1 exe)、生成 `SHA256SUMS.txt` 并正式发布。任一环节失败都保持草稿,不会发布残缺的版本。
- 暂不提供 Linux 安装包:AppImage/deb 打包依赖外部下载,稳定性与分发渠道(发行版差异、Secret Service 依赖)需要单独设计。

## 4. 签名

- macOS:默认 ad-hoc。要启用开发者签名与公证,在仓库 Secrets 配置 `APPLE_CERTIFICATE`、`APPLE_CERTIFICATE_PASSWORD`、`APPLE_SIGNING_IDENTITY`、`APPLE_ID`、`APPLE_PASSWORD`、`APPLE_TEAM_ID` 并传入构建步骤的 `env`。
- Windows:默认不签名,SmartScreen 会提示未知发布者;如有证书,在 `tauri.conf.json` 的 `bundle.windows` 配置 `certificateThumbprint` 或使用 Azure Trusted Signing。

## 5. 给贡献者的约定

1. 平台相关代码用 `#[cfg(target_os = "...")]` 隔离,并保证其它平台都有可编译的分支(哪怕是空实现)。
2. 不要在跨平台代码里直接拼 `~/Library/...` 之类的路径,使用 `home_dir()` 或 Tauri 的路径 API。
3. 新增界面快捷键文案请用 `shortcutLabel()`,不要硬编码 `⌘`。
4. 本机无法验证的平台改动,以 CI 三平台结果为准。
