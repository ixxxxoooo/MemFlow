# 产品需求文档(PRD) — OrbitBoard

## 1. 背景与目标

中小团队在使用 Trello/Jira 时普遍遇到:数据无法私有化部署、实时协作卡顿、权限粒度不足、集成扩展受限。OrbitBoard 目标是提供一套**可自托管、强实时、权限清晰**的看板协作平台,帮助 5–200 人规模的团队管理任务与知识。

### 成功指标

- 新团队 30 分钟内完成首个看板并邀请成员
- 卡片拖拽到落点延迟 < 100ms(p95)
- 月活留存(MAU retention) > 60%
- 私有化部署占比 > 40%

## 2. 用户画像

| 角色 | 描述 | 核心诉求 |
|---|---|---|
| 产品经理 | 负责需求拆解、排期 | 快速创建任务、绑定 PRD、查看进度 |
| 开发工程师 | 负责实现 | 看板状态流转、代码链接、评论讨论 |
| 设计师 | 负责视觉与交互 | 文件预览、版本管理、@ 提及 |
| 项目经理 | 负责整体推进 | 仪表盘、燃尽图、导出报告 |
| 客户/Guest | 外部协作者 |只读/受限编辑 |

## 3. 功能范围(MVP v1.0)

### 3.1 工作空间与项目

- 创建/重命名/删除工作空间;成员邀请(邮箱 + 链接)
- 项目支持颜色、图标、描述、归档
- 工作空间内项目列表,支持收藏与最近访问

### 3.2 看板

- 看板模板:空白、Scrum、Kanban、Bug 跟踪
- 列支持固定列(待办/进行中/已完成)与自定义列
- 列 WIP 限制(可选)
- 看板视图:棋盘视图、列表视图、日历视图

### 3.3 卡片

- 标题、描述(Markdown)、负责人、标签、优先级、截止日期、预估工时
- 子任务(checklist)、附件(图片/文档)、评论、活动日志
- 卡片移动:拖拽跨列/跨看板,带动画与乐观更新
- 卡片编号(如 `ORB-124`)便于引用

### 3.4 协作

- 实时光标与选区显示
- 评论 @ 提及,生成通知
- 卡片监听(watch):变更时邮件/应用内通知
- 提及与通知中心

### 3.5 搜索与过滤

- 全局搜索:标题、描述、评论、附件名
- 过滤:负责人、标签、优先级、日期范围、状态
- 保存过滤器为视图

### 3.6 权限

- 角色:Owner / Admin / Member / Guest
- 看板级别权限覆盖(可限制某看板仅部分成员可见)
- 匿名分享链接(只读,可设过期)

### 3.7 集成

- GitHub/GitLab: commit/PR 自动关联卡片
- Slack/Discord 通知机器人
- Webhook(卡片创建/移动/完成)
- REST + GraphQL 对外 API

## 4. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 首屏 < 2s;拖拽延迟 < 100ms;p95 API < 300ms |
| 可用性 | 99.5% SLA(云托管);自托管不限 |
| 安全 | HTTPS 强制、CSRF、XSS 防护、审计日志、GDPR 删除 |
| 多语言 | 中文、英文、日文(MVP 先中英) |
| 离线 | 前端本地缓存最近看板,弱网下可查看 |

## 5. 数据模型(高层)

```
Workspace 1-* Project 1-* Board 1-* Column 1-* Card
Card 1-* Comment, Attachment, Activity
User *-* Workspace (via Membership)
```

## 6. API 契约(摘要)

- 认证:`POST /v1/auth/login` 返回 `accessToken`(15min) + refresh cookie
- 资源命名:`/v1/workspaces/{id}/projects/{id}/boards/{id}`
- 实时:`wss://.../v1/realtime?board={id}&token=...`
- 分页:cursor-based,`?cursor=&limit=`

## 7. 验收标准(MVP)

- [ ] 创建看板并拖拽卡片在 3 个浏览器标签页同步
- [ ] 50 人并发编辑单看板无冲突丢失
- [ ] Guest 无法越权查看私有列
- [ ] 导出看板为 CSV/PNG
- [ ] GitHub PR 自动在卡片上显示状态
